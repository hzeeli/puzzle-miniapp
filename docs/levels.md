# 一拼成画：规则与十关设计

## 规则

棋盘固定为 4×4。每张完整照片切成左上、右上、左下、右下四片，始终保持正向。拖动任意单片或已接合的连通组，在任意合法位置与目标区域置换。同图碎片只有在正确相对位置相邻时才接合，组成完整 2×2 图片后消除。

源连块整体移动。目标区域可以只覆盖另一连块的一部分，被覆盖的片换回源区域，随后按新的邻接关系重新接合。源和目标部分重叠时，沿平移链把目标独占格的片回填到源独占格；不会复制、丢失卡片。任何一片目标越界则整次移动无效。

完成整图后按 `complete → fall → refill` 结算。下落以当前连块为刚体，遇到棋盘底部或其他片即停止。四列牌堆独立，各自从队列头向本列最低空格依次发牌。补入的片若又拼成完整图，继续结算。库存耗尽后保留空格。普通交换或移动到空格不会触发下落、补牌。

这些是所有十关共同的规则，没有通过新增旋转、锁链、限时失败等机制改变视频玩法。

## 录屏依据

用户录屏为 720×1280、30 fps、57.27 秒，展示一关的中后段。约 11 秒可以看到郁金香竖向双片整体换位；约 29–30 秒，仓鼠单片换入吉他横向双片的左格，把吉他左片换到源格、右片留在原处，证明目标连块可以被覆盖拆开。约 5.5–6.5 秒可见一次交换完成两张图片，随后清空、下落并翻牌补充。

[同类游戏的开发者商店说明](https://play.google.com/store/apps/details?hl=en_GB&id=com.neverold.jigsawflow.solitaire)也描述正确拼接后整体移动，以及小片覆盖大组后大组可能缩小。录屏未穷尽跨列悬空和复杂重叠情形；本实现对这些边界采用上面的刚体下落和平移链规则，并以测试固定其行为。

## 十关的递进结构

所有关卡版本为 **3**，开局、照片和四列队列固定。前 3 关均为 **4 张图、16 片、无备用库存**，进入后直接呈现完整棋盘。第 4–10 关均为 **8 张图、32 片、16 片备用库存**，难度变化来自初始接合程度、完整线索数量、视觉相似度和补牌分布。

“初始接边”指正确相邻的边数；“初始齐片图”指四片都已在棋盘上的图片数，并不代表已拼好。验证解长度来自确定性的合法操作序列，证明可完成，**不代表最优步数，也不等于真人体感难度**。

前三关让玩家在正式的满棋盘构图中逐步理解操作：首关先确认“交换会完成图片”，第二关学习“相连的图片可以整体搬动”，第三关自行组织更分散的碎片。前两关共同使用暖色小狗、蓝色海边小镇、白红色草莓蛋糕与粉色郁金香，让教学主要依赖清楚的形状与色块。首关两次双图完成之间，应让玩家看清完整照片、消除和剩余棋盘，再接受下一次操作；具体动画节奏由真机验收确认。

发布的客户端、云端复放、在局存档和分关榜单统一使用关卡版本 3。成绩必须与所用布局版本匹配，版本不一致的旧在局存档应重新开始当前关卡。

离线生成的交换次数依次为 2、4、8、9、12、16、20、24、28、34；第一关采用明确的两次成对错位。这个生成参数只描述布局扰动过程，不能视为距离最优解的下界。最终选出的关卡还必须满足接边、齐片图、固定验证解等约束。

素材只使用 `game/assets/photos/photo-01.jpg` 至 `photo-12.jpg` 的 12 张真实文件，同一关不重复照片。局部 token 使用本关 `photoIds` 的索引，编号为 `图片索引 × 4 + 象限`。改动布局、队列、规则或影响识别难度的素材时应提升关卡版本，并隔离排行榜成绩。

## 可继续完成的保证

四列队列不能套用每消除一图统一取四张牌的全局牌堆模型。这里让每张图片的备用碎片只出现在一列、且连续排列；该列最前面的图片可以已有部分碎片在棋盘上，后续图片必须以完整四片连续入队。

每次补牌结束，有库存的列都会填满四格。假设此时没有任何四片齐全且尚未完成的图片：若一列还剩 `r` 张备用片，涉及的未齐图片至多为 `ceil(r/4)` 张，这些图片在棋盘上的片数为 `4 × ceil(r/4) - r`，最多 3 片。不同列的库存图片不重合，所以若还有 `q` 列有库存，棋盘最多有 `3q` 片，却又必须至少有 `4q` 片填满这些列，矛盾。因此至少还有一张图片的四片都在棋盘上。无库存时，所有未完成图片也都齐片。

对任何四片齐全的图，选择棋盘内一个合法 2×2 锚点，把尚未对齐的连通组移到该图相应象限。已对齐的象限不会被后来的不同象限覆盖；每次至少对齐一片，至多四次就能完成该图，或提前触发另一张图完成。`findHint` 枚举齐片图及 9 个锚点，选择一条最短的这种局部计划的首步，不以循环增加临时接边冒充进展。它不声称求得全局最优解。

上述库存计数条件已穷举十关中后七关的 **3,395 种四列库存前缀组合**。另外，每关保存一条完整合法解，并对每关 12 组、每组最多 40 次随机合法操作后的局面继续求解。随机测试是对代码实现的补充检验，不等于穷举所有棋盘排列。

## 生成与验证

- `node scripts/generate-levels.cjs`：按固定种子和设计约束离线生成 `shared/levels-data.json`，写出独立测试解法 `tests/fixtures/level-solutions.json`。
- `npm run check:levels`：只读校验关卡编号、版本、素材文件存在且非空、队列归属、完整解法和记录的指标；不重写关卡。
- `node --test tests/rules.test.cjs tests/levels.test.cjs`：运行 37 项规则与关卡测试，包含所有库存前缀的计数证明、每个动画快照的牌张守恒、120 组随机扰动后的继续完成测试。

解法和详细指标保存在测试目录，公开关卡数据只保留说明与聚合指标。服务端从固定版本初始状态逐步复放玩家轨迹，不能相信客户端提交的完成数量。

## 共享接口

- `createState(level)`：返回独立的 `{levelId, version, photoCount, board, queues, completed, moves}`；拒绝缺失、重复或越界 token。
- `applyMove(state, from, to)`：返回 `{ok, state, events}`；不改变输入状态，非法移动返回空事件。源组始终整体移动，目标组按结果重新计算。
- 事件按 `move → complete → fall → refill` 的实际发生顺序返回，省略不需要的阶段，允许补牌引起后续完成。每个事件都有独立的 `before/after` 快照。
- `groups(board)`：返回当前连通组；`joined(board, a, b)`：判断正确相邻关系。
- `findHint(state)`：返回能通向一次完成的局部计划首步 `{from, to}`；已完成或当前没有齐片图时返回 `null`，不修改状态。
- `isSolved(state)`：同时验证每张应有图片唯一完成、棋盘空、四列库存空。
- `replay(level, moves)`：按最多 2,000 步复放，返回 `{ok, solved, state, error?, failedAt?}`。合法轨迹尚未完成时 `ok:true, solved:false`。
- `getLevel(id)`：仅接受整数 1–10。

## 难度研究依据

[King 高级关卡设计师 Lucien Chen 的 GDC 2020 演讲](https://media.gdcvault.com/gdcsummer2020/presentations/GDC2020%20Final%20PPT.pdf)把布局、设计风格与生成节奏等区分为不同难度驱动。本设计采用布局、可见线索和出牌节奏，不以更长图片列表代替难度设计。[关卡难度统计研究](https://arxiv.org/abs/2107.03305)指出仅有通关率不能完整描述局内行为，因此后续真人评估应同时看耗时、操作、提示和退出位置。
